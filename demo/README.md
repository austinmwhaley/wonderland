# demo

A single self-contained, flat light-theme HTML page presenting the result: one frozen
self-supervised encoder per event stream, reused by supervised, unsupervised, and
reinforcement-learning heads.

Open it directly — no server, no network, no dependencies:

```bash
python3 scripts/build_data_tab.py        # optional: Data tab from the relational reference
python3 scripts/build_encoder_tab.py     # optional: Encoder tab from the frozen shape/state layout
python3 scripts/build_b_demo_data.py     # optional: axes micro-visuals from the frozen model
python3 scripts/build_demo_site.py       # regenerate the page from receipts
xdg-open demo/index.html                 # or double-click the file
```

## Tabs

| Tab | What it shows |
|---|---|
| **Overview** | A five-stage morph of the same 128 state cells: **Legacy** tables → **Event Stream** as a vertical block of rows → **Encoder** layers → **Frozen State** → **Plugins** (value_90d, orders_90d, churn_90d, lookalike, action). It auto-advances every three seconds; selecting a stage jumps there and restarts the loop. Legacy uses the normal ink slider position, while the other four active stages use accent green. |
| **Data** | A **Legacy / Event stream** slider. Legacy is an RFM snapshot with one row per customer: Recency, Frequency and Monetary; the first customer is selected by default. Switch to Event stream to see that customer's raw timeline and canonical ledger, one row per event. The Event-stream slider position uses the accent green. Hover any timeline dot for its `event_ts` and `event_attributes`; the ledger shows `event_ts`, `event_type`, and `event_attributes`. No outcome labels or window markers. |
| **Encoder** | An interactive feature explorer: choose Shape, Learned state, Forecast, Uncertainty, or Heads and inspect that family's real values for one customer in a heat map. Below it, the eight content axes and the ten self-supervised objectives appear as scroll sections. |
| **Plugins** | One frozen state feeding three plugin families. **Predict** shows supervised-head bars, **Retrieve** shows the interactive unsupervised nearest-neighbour geometry, and **Act** stacks the RL known-effect recovery with the policy-value IPS trajectories. Values appear on hover; the Retrieve plot is click-selectable. |
| **Explorer** | A full-width projection of 260 held-out customers. Click a point to draw lines to its five nearest neighbours and open a large profile below: outcome, four headline numbers, preference profile, recent history, and nearest neighbours. |

## Where the numbers come from

Every value in the model tabs is generated from receipts under
`docs/report_cards/experiments/`:

- `encoder_objectives.json` — the ten self-supervised probes and their baselines
- `encoder_controls.json` — negative controls and past retention
- `encoder_b_props.json` — calibration, latent sensitivity, artifact hash
- `encoder_identity.json`, `plugin_unsupervised.json`, `plugin_rl_known.json`
- `plugin_response.json` — pre-action RL policy value
- `foundation_state.json`, `view_selection.json`, `encoder_ceiling.json`, `encoder_donor.json`
- `runtime.json`, `encoder_config.json`, `data_receipt.json` — provenance and cost

`demo/b_data.json` (built by `scripts/build_b_demo_data.py`) holds the arrays the axis panels
need: the state's singular spectrum, a predicted-vs-actual reconstruction scatter, the next-event
reliability bins, an ROC curve for churn from the state, and the per-customer identity-purity
distribution. If it is absent, the Axes section still renders its numbers and
the visuals are simply omitted.

The **Data** tab is generated separately by `scripts/build_data_tab.py`, which reads the legacy
wide table and the canonical event stream at `/tmp/opencode/t0_loop/ref_v3b_6k` and writes
`demo/data_tab.json`. It selects eight illustrative customers, previews 4 of the 51 wide-table
columns (customer, recency, frequency, monetary), and attaches each customer's full raw stream. Selecting a row opens that customer's timeline and canonical ledger below;
hovering a timeline dot exposes its timestamp and raw attribute JSON.

The **Encoder** tab is generated by `scripts/build_encoder_tab.py` into
`demo/encoder_tab.json`. It reads one customer's actual values for every published feature family
from the frozen cache and its manifest layout, alongside the state dimensions from
`encoder_config.json` and `runtime.json`. Every family map is therefore real frozen output, not a
schematic.

The Customer Explorer additionally samples the frozen cache at `/tmp/opencode/frozen_6k` and the
canonical stream.

Every number on the page is generated from the sources above, so it cannot drift from them.

## Scope

This page presents the positive results. Every number on it is a real measured number; losing or
tie-level comparisons are not displayed here. The complete record — including category identity,
anomaly/segmentation, the churn tie, and Layer-1 status — remains in `REPORT_CARD.md` and
`docs/AUDIT_CARD.md`, which are the authority.

The eight axes include A6 (Causal), which is Layer-1 work: the card states that it is evaluated
separately rather than showing a number.

## Notes

- Synthetic relational harness; no business data.
- Explorer neighbours are computed in the frozen state and are not used to form the actual outcome.
- The Data tab's legacy table is a preview: 8 illustrative rows and 4 of 51 columns, anchored on
  classic RFM (recency, frequency, monetary). Selecting a row opens the same customer's complete
  raw stream below. The ledger columns are `event_ts`, `event_type`,
  and `event_attributes`; the selected `customer_key` is shown above the timeline. Hovering a
  timeline dot shows that event's timestamp and raw attributes.
- Regenerate after any receipt or reference-data change so the page stays current.
