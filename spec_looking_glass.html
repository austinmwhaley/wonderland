1. Core Objective

Input an event stream; output a frozen foundation model whose embeddings $z_t$ support supervised, unsupervised, and reinforcement-learning heads.

1.1 The contract
Input an event stream (CESI)
Output a frozen foundation model
Interface the model's embeddings $z_t$ (read-only)

1.2 v1.0 Definition of Done

ID Area Criterion How we check it
C1 Runs itself any CESI stream works with no code changes; optional columns (actions, protected attributes) are detected automatically run a new dataset end-to-end
C2 Runs itself training finishes on its own on a held-out self-supervised score, within a data/hardware-derived budget — no hand-tuning training curve plateaus; no divergence step 0 → end
C3 Runs itself it stops and refuses instead of producing a bad model — bad numbers, collapsed embeddings, or an impossible task fail-fast checks with a saved report
C4 Healthy output the health checks (§16) pass on ≥2 diverse datasets, one check at a time per-check gate results
C5 Healthy output the frozen embeddings beat model-free baselines on every task the data contains probe tests (§11.3)
C6 Heads attach a supervised head on the frozen embeddings passes its own gate (better than raw features) independent gate (§13.3)
C7 Heads attach an unsupervised head recovers real structure from the frozen embeddings independent gate
C8 Heads attach on data with randomized actions, an RL/OPE head (white_queen/red_king) on the frozen embeddings passes its gate (real incremental effect). The model must provide whatever this needs (§13.5) independent gate
C9 Heads attach the embeddings add signal beyond raw features and are never worse than raw, under the production head E vs raw vs both ablation (§11.4)
C10 Trustworthy every result is versioned and recorded; runs are repeatable version + receipt in every artifact

The rule about results — there is no FAIL.

Result Meaning Allowed?
PASS the data contains the signal and the model beats the baseline yes
NO_SIGNAL the data provably does not contain the signal (confirmed by an independent data-side check, §15 Guardrail F) yes
FAIL the data contains the signal but the model does not beat the baseline — a defect no — blocks v1.0

Every task the data can support must PASS. NO_SIGNAL is a fact about the data, never an excuse for a weak model.

In scope Out of scope

2. Philosophy — Self-Governance

The system runs and governs itself: people set what good means (the §1.2 criteria); the system decides how to get there.

Principle In practice
Rules built into the model, not patched on later smoothness, spread, and stable memory are properties of how the model is built
Use the model's full capacity never shrink the model to pass a test; fix the training goals
Honest results a task that cannot pass is reported FAIL or NO_SIGNAL — never hidden
No hand-set numbers any leftover constant is a documented, overridable fallback, chosen at runtime and recorded
Versioning is identity a change that can alter outputs bumps the version; every artifact records how it was made
Adapt by construction a new schema / size / horizon / action space works without editing code

3. System Overview

The system is a one-way pipeline. Data flows forward only; nothing downstream ever feeds back into the encoder.

rabbit_hole (event stream)  →  looking_glass (frozen encoder)  →  heads (supervised / unsupervised / RL)
                                      │
                                      └── products DB (read-only tables)
Stage Role Produces
Layer A (rabbit_hole) source of truth: the append-only canonical event stream the stream + schema/aliases
Layer B (looking_glass) trains one self-supervised encoder, freezes it, publishes embeddings cfm_<tag>.pt checkpoint + cfm_products.duckdb tables + registry/receipts
Heads (plugins, white_queen, red_king) train small models on the frozen embeddings task artifacts that record the encoder version they used

Three ideas hold the whole design together:

  1. One encoder, many tasks. The foundation model is trained once, self-supervised, and then frozen. Every downstream task attaches a small head instead of retraining.
  2. Populations A/B. Customers are split into disjoint groups by a hash. The encoder only ever trains on population A; heads and anchors use population B. No label ever touches the encoder.
  3. Self-governance. Training derives its own budget and sizes, watches its own health, and stops when converged or when something is wrong.

4. Data Layer & CESI

4.1 Canonical event schema

Every event is exactly five fields. Anything else is folded into event_attributes.

Field Meaning
customer_key the entity (who)
event_ts event time (when)
event_type categorical token (what kind)
source_table provenance (which system)
event_attributes JSON string of all remaining key/value context

Folding rule. Given a wide table, canonicalize_row picks one source column per canonical field (by alias) and folds every other non-null column into event_attributes as JSON. Aliases include: customer_id/user_id for customer_key; timestamp/ts for event_ts; type/event_name for event_type. The SQL equivalent builds the JSON with json_merge_patch(coalesce(try_cast(event_attributes AS JSON), json('{}')), json_object(...)), and a view customer_events_canonical exposes any wide table in the five-field form without rewriting it.

4.2 Storage and IO

Format Engine How it is read
.arrow / .feather / .ipc Arrow IPC (uncompressed, memory-mapped) polars.read_ipc(..., memory_map=True) — zero-copy
.parquet / .pq Parquet polars.read_parquet(...)
.duckdb / .ddb DuckDB (read-only) duckdb.connect(read_only=True).execute("SELECT * FROM t").pl()

All reads return a Polars DataFrame (no pandas, no SQLite). Writes rebuild the five canonical columns first if the frame is wide, then write in the format's native path.

4.3 Reading attributes whether column or JSON

The encoder's content channels — brand, entity_type, entity_id, value — may sit either at the top level (wide fixtures) or inside event_attributes (canonical). The reader tries the column first; otherwise it extracts from JSON (json_extract_string in DuckDB, str.json_path_match in Polars), casting value to float. This one code path lets the encoder consume both shapes.

5. Data Path (point-in-time)

5.1 The single day boundary

as_of_epoch(s) interprets a naive ISO date as UTC midnight. This one helper is shared by the encoder cut, the daily job, and inference lookups, so "the day" means the same thing everywhere. as_of is always passed, even in production, so backtests and production run the identical path.

5.2 Point-in-time cut

Before anything else, the raw stream is filtered to event_ts ≤ as_of. Keys, splits, anchors, sequences, and products are all built from this leak-free prefix. Nothing after the cutoff is ever visible.

5.3 Population split A/B

Each key is assigned by a stable hash:

split(key) = "B" if md5(f"{split_seed}:{key}") % 1000 ≥ split_a_frac·1000 else "A"

split_a_frac = 0.7. A and B are disjoint by construction. The seed rotates monthly (md5(base_seed + "YYYY-MM")) so the split re-randomizes each cycle while staying reproducible within a cycle. The encoder trains only on A; population B is reserved for anchors/heads.

5.4 Sampling

A sample is a seeded uniform draw from a population:

draw_sample(keys, split, side, n, seed): shuffle its own RNG, take the first n

sample_a builds the encoder-training sample; sample_b_customers draws the head/anchor sample. Sizes are chosen by the ladder (the smallest sample whose products match the best within paired noise), not hardcoded.

5.5 Anchors

For each customer, n_anchors (default 6) uniformly random days are drawn in [history_start, data_end − 1 day], independent of any label. The anchor timestamp travels with the sequence and is where the embedding is read.

5.6 Sequence construction

  • Partition the frame once by customer_key (ordered by time).
  • Events whose type is a declared exogenous/company action are removed from the token stream and become covariates — the model must tell "what the user did" from "what our system did".
  • Each customer's history is cut into windows of at most seq_len (default 128) ending at an anchor (for B) or spanning the whole history (for A). Very short histories (< 3 events) are dropped for training.
  • Each sequence carries: customer, group, anchor_epoch, event_type, brand, entity_type, entity_id, value, event_ts, ts, co.

5.7 Collation, masking, padding

A batch is padded to the longest sequence; pads use the "unknown" token id and mask = 0. Derivable signals:

  • dt[t] = log1p(max(ts[t] − ts[t−1], 0)) — inter-event gap.
  • tod = [sin, cos] of time-of-day and [sin, cos] of day-of-week (periodic, no calendar literals).
  • co = [is_company_action, log1p(gap)] — exogenous covariates.
  • Inside the recurrence, pads hold the state: decay ← 1, bx ← 0 on padded steps.

Targets exclude pads and company-action steps, so the model never predicts the system's own interventions as if they were user behavior.

6. Tokenization

The vocabulary is learned from data: sorted sets of every event_type, brand, and entity_type seen in the A-training sequences, each with one extra "unknown" slot.

Each event becomes a vector (width chan = dim / n_experts):

x_t = emb_et[event_type] + emb_brand[brand] + emb_ent[entity_type]
      + w_val(value) + w_dt(log1p gap) + w_co(covariates) + w_tod(tod)
Term Kind Notes
emb_et, emb_brand, emb_ent embedding tables unknown index used for missing/pad
w_val linear on scalar value/magnitude
w_dt linear on log1p(Δs) continuous-time gap
w_co linear on 2 covariates exogenous/company + gap
w_tod linear on 4 Fourier features time-of-day, day-of-week

RMSNorm (per-sample, per-timestep; x · rsqrt(mean(x²)+eps) · gain) is applied to the token stream at the model input and to the readout — normalization by construction, never using batch statistics.

7. Encoder

The encoder is a selective multi-scale state-space model (SSM). It reads the event sequence and produces, at every step, an output vector y_t; the final recurrent state is the customer's summary.

7.1 The recurrence

Per channel, per step:

$$\delta_t = \mathrm{softplus}(W_\delta x_t + b_\delta), \qquad \mathrm{decay}_t = e^{-\delta_t} \in (0,1)$$

$$h_t = \mathrm{decay}_t \odot h_{t-1} + (1-\mathrm{decay}_t)\odot (W_B x_t), \qquad y_t = W_C h_t$$

This is a leaky integrator whose leak is selected by the input: b_δ is a learned per-channel vector (a log-uniform spectrum from fast to slow), and the data can speed up or slow down each channel. Because decay ∈ (0,1) always, the memory is contractive by construction — it can neither explode nor freeze.

A learned skip (the SSM D term), identity-initialized, adds the current token back into the readout.

The whole recurrence is solved by a vectorized affine prefix scan in O(log T) passes (Hillis–Steele). Each step is an affine map f_i = (decay_i, drive_i); composing is (d_i d_j, d_i b_j + b_i). Only log T Python iterations occur; the work is tensorized over time. A stored initial state h0 is applied exactly as H_t += (∏_{m≤t} decay_m) · h0.

7.2 Multi-scale and band isolation

One wide state covers all timescales. The b_δ spectrum is spread log-uniformly (default range −1.5 to 3.0), so some channels remember seconds and others weeks within a single trunk. Optional band isolation zeroes the cross-band entries of W_δ and W_B (split derived from the learned b_δ median), so the slow band is driven only by slow-band input — separation is structural, not a loss term.

An expert-bank variant (n_experts independent selective SSMs) exists but the default is the unified trunk (n_experts = 2, unified_ssm = True).

7.3 The low-pass intent filter

To turn spiky per-event content into smooth local rates, a per-channel learned EMA low-pass runs before the recurrence:

$$\tilde{x}_t = r \odot \tilde{x}_{t-1} + (1-r)\odot x_t$$

The retention r is learned, initialized from the stream's own statistics: the content-change probability p gives an average run length L = 1/(1-p), and r = exp(−ln2 / L). A stream with 77% type-change gets r ≈ 0.85 (heavy smoothing); a calmer stream gets r ≈ 0.57. No hand-set partition of features.

7.4 The donor boundary

The consumed representation z = boundary(proj(h)) is built in two steps, in this order:

  1. learned projection proj (a linear readout), and
  2. a per-sample boundary transform.

The default boundary is a Cayley orthogonal isometry R = (I−S)(I+S)^{−1} (S skew-symmetric), so R is well-conditioned (κ = 1) and invertible. It does not whiten and does not manufacture rank — it preserves the trunk's spectrum. It is scaled by a conservation factor boundary_scale = sqrt(P_in / tr(Σ_readout)), holding the readout energy to the input band power (R_cons ≈ 1).

A legacy global-EMA ZCA path remains as a fallback: maintain a running mean/covariance and approximate Σ^{−1/2} with a Newton–Schulz iteration (matmuls only, spectral-norm normalized, condition-capped by eps), with an entropy-weighted update rate. It is fit after proj (whitening h first and then projecting re-collapses rank — measured). It is frozen at inference so training and serving share one map.

7.5 Event-identity bypass (dedicated readout dims)

The recurrent state is a low-pass aggregate; it washes out the immediate event. To give a linear head the Markov transition at full scale — with no loss hack — the readout reserves the first 2·(n_et+1) dimensions:

Readout dims Content
[0 : n_et+1) one-hot of the current event type e_t
[n_et+1 : 2·(n_et+1)) one-hot of the previous event type e_{t-1}
[2·(n_et+1) : dim) the SSM readout (untouched)

This is a bypass, not a bottleneck: raw one-hots are written at full scale. It is opt-in (event_residual).

7.6 Inference (constant-time state advance)

The recurrent state is the public representation. Serving never re-runs the whole history:

  • fade (idle advance): h · exp(−ln2 · Δt / half_life) — O(1) elementwise.
  • absorb (event advance): fade the stored state to the first new event, then run only the new events.

The half-life derives from the p95 of within-customer gaps.

8. Objectives (self-supervised)

All objectives train jointly; none uses labels. Targets come from the same batch (next event, masked event, future window, etc.). Regression targets are standardized by the batch's own moments so every loss is O(1).

Objective What it teaches Loss
next next event type cross-entropy of head_next(y_{t}) vs e_{t+1}
entity next entity type cross-entropy vs entity_{t+1}
dt next gap MSE of standardized log1p Δt
value next magnitude MSE of standardized $\log(1+|value|)$
occur will an event occur within a horizon BCE at a data-derived gap threshold
order temporal order Bradley–Terry margin between the true and a random event
mask reconstruct a redacted event cross-entropy of head_mask on masked positions (causal, left-context only)
contrast instance discrimination (uniformity) NT-Xent over normalized final states
jepa predict the future latent (EMA target encoder) negative cosine between predicted and target future state
sf long-horizon successor features MSE to the exact discounted future aggregate of $\phi=[\log(1+|value|),\ \text{one-hot event}]$, via a reverse affine scan
query serving path: read the faded state at an arbitrary time cross-entropy of next event + MSE of gap, after fading h to a random query time
agg exact multi-horizon window sums MSE of standardized [log1p(count), log1p(value_sum)] over a derived horizon

Two design points worth stating:

  • query is the objective that makes the frozen model usable at serving time: it trains the readout to answer from a faded state, exactly as inference will.
  • sf uses a successor-feature target built by an exact reverse scan over the event clock (discount γ sampled from [0, 0.999]), so long-horizon value is learnable out of the box without a decision label.

A deprecated set of soft-invariant terms (variance, rank, redundancy, decorr, spectrum, volume, iso, trajectory, commutation, ortho) is opt-in only; it was removed from the default objective because structural mechanisms replaced it (§15).

9. Optimizer

9.1 Weighting

Mode Rule Notes
equal (default) sum the losses as-is no dynamic re-weighting
dwa per-task weight from the rate of change, w = K·softmax(r/T) scale-free: each loss divided by its own EMA unit
uncertainty Kendall log-variance per task legacy

A bounded compression term (AIB) can be added, its multiplier tuned by dual ascent on batch participation ratio.

9.2 Task–structure projection (PCGrad)

Losses are split into task (predictive) and invariant (geometry). When the invariant gradient conflicts with the task gradient, it is projected onto the null space of the task gradient, so structural pressure can never reduce predictive skill. With the default objective set the invariant set is empty, so this is a no-op unless soft invariants are enabled.

9.3 Memory bank and closed-loop governor

An 8192-state FIFO (GeometryBank) holds recent projected states. Each step it adds decorrelation, an eigenvalue floor, and a log-det volume barrier, multiplied by a closed-loop multiplier:

$$\lambda \leftarrow \mathrm{clip}(\lambda\cdot e^{\alpha\,(\mathrm{target} - \mathrm{rank})},\ 1,\ 10^6)$$

So when the bank's participation-ratio (rank) falls below target, the structural pressure grows; when it is on target, the pressure relaxes. The multiplier history is recorded.

9.4 Step size (Armijo per step)

Adam is the base optimizer. Each step, the training loss (with current weights) is evaluated before and after the candidate step:

  • if the new loss is non-finite or clearly worse → revert the step, halve the learning rate (floored at 10% of base to avoid collapse);
  • otherwise accept and grow the learning rate (capped).

This makes training stable step 0 → end without estimating a global curvature bound. (Divergence is a hard failure, never rescued by rolling back to a lucky earlier state.)

9.5 Whitening

Before saving, the boundary transform is fit on the consumed representation proj(h) (not h), full-precision, with the current transform disabled. Fail-safe: if whitening does not improve participation ratio, it saves an identity transform and records that it was a no-op.

9.6 Warm-start

Auto warm-start continues from the most recent compatible checkpoint: same behavior version, same resolved architecture (seq_len, dim, half_life, sf_mode), same objective set, and as_of no later than this run. Compatibility is required so a warm start can never change behavior silently.

10. Training

10.1 Derived budget and sizes

Nothing is a fixed count. From the data and hardware:

Quantity Derivation
seq_len p90 events/customer, clipped to [8, 256]
dim from sqrt(N) · log2(vocab + sequences) · (1 + event-type entropy), clipped to a power of two in [16, 256]
batch sequences/32, power of two, capped by available GPU memory
state_half_life_days p95 of within-customer gaps, clipped to [1/24, 365] days
agg_horizons_days quantiles (0.5/0.9/0.99) of within-customer gaps
budget 15 · ceil(N/batch) · sqrt(dim/64), clipped to [50, 200000]
eval_every, patience budget-scaled

Architecture identity derives from the full working base; batch and budget derive from the actual sample, so the sample ladder scales honestly. Any explicit override wins and is recorded.

10.2 Convergence

Training runs in evaluation chunks. After each chunk it measures a held-out metric and:

  • tracks a noise floor from recent evaluations (tol = 0.5·std of the last window);
  • keeps the strictly best held-out state ever seen;
  • stops when improvement stalls for patience evaluations (converged), or on budget;
  • divergence guard: a metric far above the noise floor marks the run unstable and stops it as a hard failure (no green).

10.3 Best-state selection

Selection uses a stationary, equal-weight held-out sum in the scale-free unit system — never the same self-referential weighting the model is optimizing. A non-finite term or a non-positive metric surfaces as failure, not a masked pass.

10.4 Step-0 tensor-health harness

Before training, on a small batch, the model is checked and must pass:

Check Rule
magnitude per-token RMS within [1/κ, κ] (κ=2); absolute max bounded
variance no collapsed variance
spectral bound every decay < 1 (contractive)
rank state participation ratio > 1 (not rank-1)
determinism identical output on a repeated forward

10.5 Receipts

Every run writes a registry JSON with version, tag, data signature, as_of, split seed, warm-start source, resolved config and overrides, governor outcome, portfolio result, task weights, loss scales, bank stats, and whitening receipt. Every artifact is traceable to the inputs and settings that produced it.

11. Evaluation

11.1 Portfolio (structure skill, geometry, canary)

  • Structure skill per objective: the held-out loss on real data minus the loss on destroyed data (content permuted within each customer), grouped by customer, with fold standard error. Positive skill means the model uses temporal structure. Some objectives are report-only.
  • Identifiability ceiling: a model-free first-order baseline (conditioning on the previous event) is fit and scored on the same folds; if the achievable signal is at the noise floor, the objective is NO_IDENTIFIABLE_SIGNAL.
  • Verdict: PASS if skill exceeds twice its standard error; NO_IDENTIFIABLE_SIGNAL if the ceiling is at the floor; otherwise FAIL.
  • Geometry gate: participation-ratio fraction of the consumed states, compared to a fraction of the stream's own achievable (whitened) capacity, with the finite-sample Marchenko–Pastur null shown for reference. Also checks the conservation ratio and a stability flag.
  • Canary probes: the state must not predict the A/B arm or the time period (< chance × 1.5) — a leak detector.

11.2 Intrinsic proofs

Five representation-space checks on frozen states:

Proof Gate
disentanglement channel mutual information below a floor vs a shuffled null
out-of-time stability principal-angle subspace overlap across time splits above 0.85
local Lipschitz perturbing one event by ±1 day changes the state by less than a bound
trajectory smoothness slow-state velocity direction cosine > 0
Markov sufficiency predicting a future window from the state beats a shuffled null

11.3 Probe harness (frozen)

Encoder weights are frozen and every head is trained on top. For each probe objective, the model's held-out score is compared to model-free baselines (unigram, previous-event transition, historical mean, previous value), each with standard error. The verdict rule: PASS if the model beats the stronger baseline by twice the standard error; NO_IDENTIFIABLE_SIGNAL if the baselines are already at the noise floor; else FAIL.

Additional diagnostics: event-identity decodability (can a linear probe read the current event from z_t?), next-event slices, and three named capabilities — pacing, boundary (is the next event a session reset?), and uncertainty (is unusual input detected?). Plain CE/MSE, no class weights.

11.4 Sufficiency battery (the universal-donor gate)

The donor claim is tested by an ablation on the same held-out rows, under the production head:

Arm Features
E frozen embeddings
R causal raw aggregates (recency, tenure, count, value, gaps, order stats, per-type counts)
E+R concatenation
Scr row-shuffled embeddings (null)

The verdict requires, per target: E beats shuffled (adds signal), E is not materially worse than raw, and E adds unique signal beyond raw (partial-correlation lower bound > 0). Across the 8 targets, the donor is "universal" when unique coverage ≥ threshold and standalone/coverage ≥ 0.8.

12. Products (the state store)

cfm_products.duckdb is written by exactly one component (StateStore); everything downstream reads it.

Table Columns Purpose
customer_state key, as_of_epoch, version, dim, state[], embedding[], last_event_ts the live recurrent state per customer
anchor_embeddings key, anchor_epoch, version, dim, embedding[] entity-pooled readout at anchors
donor_embeddings same as anchor_embeddings state-consistent readout (boundary(proj(h))) — the production feature
state_embeddings key, as_of_epoch, version, dim, embedding[] materialized daily serving features
encoder_samples key, split, version the persisted A/B assignment
state_job_receipts as_of_epoch, version, counts, device, wall time, ran_at one row per daily job / day-1 close

Flow: build_products writes splits, runs every customer's full history to a state, closes day 1 (fade idle states + materialize embeddings + receipt), and writes anchor/donor embeddings. The daily job reads only the new window (last_as_of, day], absorbs new events, fades idle customers, rematerializes embeddings, and refuses to run backwards. Dense per-week/daily states are emitted for downstream decision logs.

13. Head Interfaces

13.1 Plugin contract

Object Role
PluginSpec name, kind, target, window_days, version, revision; tag = name_version r revision
Dataset frozen embeddings X, labels y, keys, anchor times, a raw baseline x_base, and meta
save_artifact writes {spec, tag, payload} and an as-of-stamped archive

Dataset reads from the products DB, builds labels only from windows that close by the last observable order, and records the encoder version(s) present in the feature table.

13.2 Targets

A Target declares kind (binary/continuous), window, and which feature table it reads. The production propensity target reads donor_embeddings — a pure function of the state, so it is reproducible at inference. Continuous CLV reads anchor_embeddings.

13.3 Supervised head and gates

Heads are fit on one shared grouped split (by customer), with a bake-off across model families; ties are broken by paired standard error. Gates are explicit and per-capability:

Gate Rule
discrimination AUC/lift beats the baseline by > 2·SE (paired)
calibration calibration gap within a derived tolerance; Brier below baseline
continuous rank correlation above a floor and not worse than the trailing baseline

13.4 Encoder-version pinning

A head records the encoder tag it learned from. If the feature table holds zero or more than one distinct encoder version, the head refuses to train (a mixed-version table would train a null-pinned head that passes and fails later). Inference rejects a version mismatch.

13.5 RL heads (white_queen / red_king)

The foundation model must enable offline policy evaluation and counterfactual evaluation. That imposes hard requirements on the data contract and the encoder:

Requirement Why
preserve randomized action arms and logged propensity through CESI causal identification needs the action and its selection probability
expose actions distinctly from user events (covariates, and — where needed — an action-gated operator B(a_t)) the model must separate "what the system did" from "what the user did"
per-customer, calibrated uncertainty in the embedding path OPE/counterfactual estimates must carry intervals, not point values

With those in place, white_queen (offline policy evaluation / certification) and red_king (counterfactual evaluation) attach to the frozen embeddings as downstream heads and must pass their own gates. On streams without randomized arms, these heads correctly refuse.

14. CLI & Versioning

14.1 Commands (run from the repo root)

Command Does
train train the encoder + build products (also closes day 1)

Key flags: --db, --as-of, --customers, --anchors, --sample-a, --sample-b, --warm-start {auto,none,tag}, --tag, --out-dir, --set KEY=VALUE (repeatable; applied after derivation and recorded). The daily job is a separate command (--as-of = the day being closed).

14.2 Versioning

Versions are pre-1.0 semver MAJOR.MINOR.PATCH (0.MAJOR.MINOR), with an r data/score revision appended to form the tag: <version>r<revision> (e.g. 0.6.4r162610). The version encodes behavior: a change that can alter outputs bumps the version; every artifact records its inputs, config, and version (DEC-058).
