Reinforcement Learning Lab

An RL lab: combine any algorithm with any compatible environment, log everything to JSONL, and visualize comparisons with matplotlib.

reinforcement_learning/
├── algorithms/          # every RL algorithm behind a common interface
│   ├── registry.py      # the algorithm table (name, source, family, compat tags, ...)
│   ├── tabular/         # Sutton & Barto Ch. 4-8, 12 (MC, TD, n-step, traces, Dyna, DP planning)
│   ├── approx/          # Ch. 10-13 + modern (semi-gradient SARSA, REINFORCE, AC, A2C, PPO, TRPO)
│   └── deep/            # DQN family (DQN/Double/Dueling/Prioritized/C51/QR/Rainbow), DDPG, TD3, SAC
├── environments/        # registry of gymnasium environments (+ bandit testbed)
├── experiments/         # configs and the generic train runner
├── tracking/            # MetricTracker -> results/runs/<run_id>/metrics.jsonl
├── visualization/       # learning-curve plots from logged runs
├── run_experiment.py    # CLI entry point
├── benchmark.py         # run the whole algorithm x environment grid
├── visualize.py         # compare any runs
├── generate_docs.py     # rebuilds ALGORITHMS.html + ENVIRONMENTS.html from the registry
├── pyproject.toml       # dependencies (managed by uv)
├── .python-version      # pins the project Python (3.12 — newest with Intel-Mac torch wheels)
├── ALGORITHMS.html      # generated algorithm table (implemented + stubs)
└── ENVIRONMENTS.html    # generated environment table

Setup

uv sync          # creates .venv and installs deps (torch, gymnasium, numpy, matplotlib, markdown)

Then run everything from the reinforcement_learning/ directory with uv run:

uv run python run_experiment.py --list                  # see the algorithm + environment tables
uv run python run_experiment.py --algo dqn --env cartpole --steps 30000
uv run python run_experiment.py --algo sarsa --env cliffwalking --steps 20000
uv run python visualize.py --filter env=cartpole        # compare all cartpole runs
uv run python visualize.py --filter algo=dqn --env=cartpole --loss
uv run python benchmark.py --steps 20000                # full grid, then visualize

Each run (metrics, config, checkpoint) lives in results/runs/<algo>_<env>_<timestamp>/. The whole grid is resumable — re-running benchmark.py --resume skips finished combos.

Compatibility

The registry tags every algorithm with action_space, state_space, and a compatible_envs list. Mismatched combos fail fast:

$ uv run python run_experiment.py --algo dqn --env pendulum
incompatible combo: dqn is not listed as compatible with pendulum. Compatible: ['cartpole', ...]

Quick guide: - Bandits (ucb_bandit, thompson_sampling, ...) run on the bandit testbed (S&B Ch. 2). - Planning (policy_iteration, value_iteration, ...) need an env with an explicit model (frozenlake, cliffwalking). - Tabular methods (qlearning, sarsa, dyna_q, ...) run on tabular envs (cliffwalking, frozenlake, blackjack). - Discrete deep RL (dqn, rainbow, ppo, ...) run on cartpole, lunar, mountaincar, acrobot. - Continuous control (ddpg, td3, sac, ppo, ...) run on pendulum, mountaincar_continuous.

Logging format

Every run writes results/runs/<run_id>/:

  • metrics.jsonl — one JSON object per event: {timestep, episode, return, loss, eval_return?, t}
  • config.json — full config (algo, env, hyperparameters, seed)
  • checkpoint.pt — saved agent weights/Q table

The same schema is used by every algorithm, so visualize.py can compare any combination of runs.

Adding an algorithm

  1. Write a class with act(state, eval=False), train(env, config, tracker), save/load(path) (subclass BaseAgent).
  2. Add an entry to algorithms/registry.py with its metadata.
  3. uv run python generate_docs.py to refresh the tables.

Not-yet-implemented algorithms (mcts, muzero, her, decision_transformer, ...) are listed as stubs in the registry so the table stays complete.
